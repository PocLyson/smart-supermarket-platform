# 小程序“设置”页面设计

## 目标

将账号注销从“我的”页面移入独立“设置”页面，并把账号基础操作、隐私相关入口和本地数据管理集中在同一位置。“我的”页面继续承担订单、门店服务和默认取货信息管理，不把默认取货信息迁入设置。

## 信息架构

### “我的”页面

保留：

- 用户登录状态和微信登录入口；
- 我的订单；
- 门店服务；
- 默认取货信息；
- 底部悬浮导航。

调整：

- 新增一行“设置”入口，点击进入设置页；
- 移除页面底部现有的“退出登录”和“注销账号”操作。

### “设置”页面

设置页使用与现有深蓝视觉系统一致的白底分组卡片，分为以下三组：

1. 账号设置
   - 当前账号：展示“微信账号 · 已登录”或“未登录”；
   - 退出登录：仅登录后显示，点击后进行一次确认。
2. 隐私设置
   - 用户服务协议：进入现有协议页面；
   - 隐私政策：进入现有隐私政策页面；
   - 清除本地使用记录：清除购物车、搜索记录和未完成的本地待提交订单。
3. 账号管理
   - 注销账号：仅登录后显示，使用红色警示文字；
   - 保留现有两次确认、未完成订单拦截和注销结果处理。

## 交互与边界

- “设置”入口对登录和未登录用户都可见，方便未登录用户查看协议和隐私政策。
- 未登录时不显示“退出登录”和“注销账号”，账号状态显示“未登录”。
- 清除本地使用记录前显示确认弹窗，并明确说明：
  - 会清除本机购物车、搜索记录和待提交订单；
  - 不会删除账号、服务端历史订单或默认取货信息。
- 清除完成后显示轻提示；当前登录状态保持不变。
- 退出登录只清除登录会话，不删除账号和服务端资料；完成后返回“我的”页面并刷新为未登录状态。
- 注销成功后清除登录会话及全部本地业务数据，返回“我的”页面并显示未登录状态。
- 注销失败时留在设置页展示服务端错误；存在未完成订单时向用户说明需先完成或取消订单。
- 默认取货姓名和手机号仍只在“我的”页面查看和编辑。

## 页面导航

```text
我的
├─ 我的订单
├─ 门店服务
├─ 默认取货信息
└─ 设置
   ├─ 账号设置
   │  ├─ 当前账号
   │  └─ 退出登录
   ├─ 隐私设置
   │  ├─ 用户服务协议
   │  ├─ 隐私政策
   │  └─ 清除本地使用记录
   └─ 账号管理
      └─ 注销账号
```

## 组件与代码边界

- 新建独立的 `pages/settings` 页面，负责设置项展示、跳转、退出登录、本地数据清理和注销交互。
- 复用现有 `profileService.deleteAccount()`、会话存储、购物车存储和注销二次确认逻辑，不新增后端接口。
- 将注销确认逻辑放入可复用模块，避免“我的”页与设置页重复实现。
- “我的”页只负责进入设置，不再直接执行退出或注销。
- 更新用户服务协议和隐私政策中的注销路径描述为“我的—设置—注销账号”。

## 视觉规范

- 页面背景、卡片圆角、分割线、字号和间距沿用当前小程序设计令牌。
- 普通设置项使用深色标题、灰色辅助说明和右侧箭头。
- “退出登录”使用普通账号操作样式，不与主按钮竞争。
- “注销账号”只使用红色文字和独立危险操作分组，不使用大面积红色按钮。
- 每个可点击设置项保证不小于 `88rpx` 的触控高度。

## 错误处理

- 协议页跳转失败时显示轻提示。
- 本地数据清理异常时不显示成功提示，并告知用户稍后重试。
- 退出登录和注销操作处于处理中时禁止重复点击。
- 注销网络结果不确定时保留当前页面状态，引导用户重新加载账号状态，不直接宣称注销成功。

## 验收与测试

- “我的”页存在设置入口，且不再显示退出登录和注销账号。
- 默认取货信息仍可在“我的”页编辑和保存。
- 登录与未登录状态下，设置页展示符合设计。
- 用户服务协议和隐私政策入口可以打开对应文档。
- 清除本地使用记录只清除指定本地业务数据，并保留登录状态和默认取货信息。
- 退出登录后会话失效并返回未登录状态。
- 注销仍经过两次确认；成功、未完成订单拦截和网络异常均有正确反馈。
- 法律文本中的注销路径与实际页面一致。
- TypeScript 类型检查和小程序自动化测试全部通过。
