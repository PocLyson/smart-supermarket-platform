# 订单备注、门店公告、联系商家与商品归档设计规格

- 日期：2026-08-01
- 状态：已确认，待实施计划
- 项目：鲁能超市李老家分店智慧超市系统
- 适用端：微信小程序、商家后台、服务端

## 1. 背景与目标

本次迭代解决四项实际经营需求：

1. 顾客下单时可以给整张订单填写备注。
2. 商家可以在后台发布门店公告，并在小程序内展示。
3. 顾客可以通过小程序联系商家，包括微信客服和门店电话。
4. 商家后台可以删除商品，同时保护历史订单和经营数据。

本次选择完整的服务端持久化方案。订单备注、公告和商品归档状态均进入数据库，并由服务端统一校验权限与业务规则。

## 2. 范围边界

### 2.1 本次包含

- 整单备注，最多 100 个字符。
- 后台公告的草稿、发布、下线、编辑和删除。
- 小程序首页公告入口、公告列表和公告详情。
- 小程序“我的”页及订单详情页的联系商家入口。
- 微信客服入口和拨打电话入口。
- 后台商品软删除、已删除筛选和恢复。
- 权限控制、审计记录、异常状态和自动化测试。

### 2.2 本次不包含

- 单个商品逐项备注。
- 订单提交后修改备注。
- 微信订阅消息或模板消息推送。
- 自建聊天系统、聊天记录存储或客服坐席系统。
- 商品物理删除。
- 顾客端查看已删除商品。

## 3. 已确认的总体方案

采用“克制整合”界面方案：

- 首页公告位于首页横幅之后、热门分类之前，以紧凑的单行公告条展示，不挤压顶部搜索区域。
- 订单备注在确认订单页使用独立小卡片，保持可发现性和清晰层级。
- 联系商家入口同时出现在“我的”页门店服务区域和订单详情页，减少顾客寻找路径。
- 后台商品删除是次级危险操作，不使用高视觉权重的大面积红色按钮。
- 所有新增界面继续使用当前深海军蓝视觉系统、圆润卡片和现有间距规范。

## 4. 小程序体验设计

### 4.1 订单备注

确认订单页在商品清单之后、支付信息之前增加“订单备注（选填）”卡片。

- 输入形式：多行文本输入。
- 占位文案：`如：饮料要常温、易碎品请轻放`。
- 显示字符计数：`0 / 100`。
- 备注为空时允许正常提交。
- 提交时去除首尾空白；去除后为空则保存为 `null`。
- 订单提交成功后不可修改。
- 小程序订单详情和后台订单详情仅在备注非空时展示“顾客备注”。

### 4.2 门店公告

首页横幅之后展示最新一条已发布公告：

- 单行展示公告标题，超长文本省略。
- 左侧显示“门店公告”，右侧显示进入箭头。
- 点击后进入公告详情。
- 首页公告接口失败或当前无公告时，整个公告条隐藏，不影响购物主流程。

新增公告列表页和公告详情页：

- 列表仅展示已发布且未下线公告，按发布时间倒序排列。
- 列表项显示标题和发布时间。
- 详情页显示标题、发布时间和正文。
- 顾客打开详情后公告若已下线，展示“该公告已结束”，并提供返回入口。
- 公告正文只按纯文本渲染，不执行 HTML。

### 4.3 联系商家

“我的”页的门店服务区域增加两个并列入口：

- `联系在线客服`：调用微信小程序客服会话能力。
- `拨打门店电话`：调用微信拨号能力，号码为 `18653045492`。

订单详情页增加紧凑的“联系商家”区域，同样提供在线客服和拨打电话两个入口。

降级规则：

- 微信客服未配置、不可用或调用失败时，提示顾客拨打门店电话。
- 拨号调用失败时展示完整电话号码，方便顾客复制或手动拨打。
- 系统不保存客服聊天内容。

## 5. 后台体验设计

### 5.1 公告管理

后台新增“公告管理”菜单，包含公告列表和编辑页面。

公告状态：

- `DRAFT`：草稿。
- `PUBLISHED`：已发布。
- `OFFLINE`：已下线。

业务规则：

- 草稿可以编辑和删除。
- 发布时写入发布时间。
- 已发布公告必须先下线，之后才能编辑或删除。
- 下线公告可以重新编辑并再次发布。
- 标题最多 60 个字符。
- 正文最多 2000 个字符。
- 列表支持按状态筛选，并显示最后更新时间、发布时间和操作人。

发布、下线和删除均要求二次确认，其中删除使用危险操作提示。

### 5.2 商品删除与恢复

商品管理页增加商品归档筛选：

- 默认显示正常商品。
- 可切换查看已删除商品。
- 可按现有分类、库存条件与归档状态组合筛选。

正常商品行增加“删除”文字操作。点击后显示二次确认：

`删除后商品将立即下架，顾客无法继续购买；历史订单不会受影响。`

确认后执行软删除：

- 商品标记为已归档。
- 商品自动下架。
- 顾客端商品列表、搜索、详情和推荐接口不再返回该商品。
- 历史订单继续保留商品快照并正常展示。

已删除商品列表提供“恢复”操作。恢复后商品仍保持下架，商家需要检查库存、价格和图片，再手动上架。

## 6. 数据设计

### 6.1 订单备注

在订单表增加：

- `customer_note VARCHAR(100) NULL`

规则：

- 仅创建订单时写入。
- 服务端去除首尾空白并校验最大长度。
- 不与订单状态流转备注混用。
- 创建成功后不提供修改接口。

### 6.2 商品归档

在商品表增加：

- `archived BOOLEAN NOT NULL DEFAULT FALSE`
- `archived_at TIMESTAMP NULL`
- `archived_by VARCHAR(...) NULL`

软删除时同时将 `on_shelf` 设为 `FALSE`。恢复时只清除归档字段，不自动上架。

历史订单必须继续使用下单时的商品名称、价格、数量等快照，不依赖当前商品是否归档。

### 6.3 公告

新增公告表，至少包含：

- `id`
- `title`
- `content`
- `status`
- `published_at`
- `created_by`
- `created_at`
- `updated_by`
- `updated_at`

列表排序以 `published_at DESC` 为准；未发布草稿不对小程序公开。

### 6.4 联系方式

门店电话作为集中式门店配置提供给小程序，当前值为 `18653045492`。页面不得在多个位置各自维护不同号码。微信客服使用微信小程序原生客服能力，不在数据库保存会话内容。

## 7. 接口设计

接口命名在实施计划阶段按现有项目路由规范落位，能力要求如下。

### 7.1 小程序接口

- 创建订单请求增加可选字段 `customerNote`。
- 订单详情响应增加可选字段 `customerNote`。
- 获取最新已发布公告。
- 分页获取已发布公告列表。
- 获取已发布公告详情。
- 获取门店联系方式。

所有面向顾客的商品查询默认且强制排除已归档商品。

### 7.2 后台接口

- 公告列表、详情、创建、修改、发布、下线和删除。
- 商品软删除。
- 已删除商品筛选。
- 商品恢复。
- 后台订单详情返回 `customerNote`。

删除、恢复、发布和下线接口必须具备幂等保护，重复请求不能造成非法状态或重复审计记录。

## 8. 权限与审计

- 老板账号可以创建、编辑、发布、下线和删除公告。
- 老板账号可以删除和恢复商品。
- 收银员继续处理订单和库存，但不能管理公告、删除商品或恢复商品。
- 服务端必须执行权限校验，不能只依赖前端隐藏按钮。
- 公告发布/下线/删除、商品删除/恢复写入审计日志，记录对象、动作、操作人和时间。

## 9. 异常与一致性规则

- 订单备注前后端均限制 100 个字符，按纯文本展示。
- 公告接口失败时不阻断首页商品、分类和购物功能。
- 公告详情在打开后被下线时显示明确结束状态。
- 已归档商品不能加入购物车。
- 购物车中的商品在之后被归档或下架时，结算必须失败并提示：`部分商品已下架，请移除后重试`。
- 商品归档不得破坏历史订单、取货码、金额和状态记录。
- 删除和恢复操作发生并发冲突时，以服务端最终状态为准，并返回可理解的提示。
- 客服不可用时必须保留电话联系通道。

- 数据库迁移测试。
- 订单备注为空、正常、超长和特殊字符测试。
- 公告完整状态流转测试。
- 公告公开查询只返回已发布数据的测试。
- 商品软删除、自动下架、公开查询排除和恢复测试。
- 归档商品结算拦截测试。
- 历史订单兼容测试。
- 老板和收银员权限边界测试。
- 审计日志测试。

### 10.2 商家后台

- 公告列表、筛选、编辑、发布、下线和删除交互测试。
- 商品删除确认、已删除筛选和恢复测试。
- 权限不足时按钮与接口错误处理测试。
- 后台订单详情展示顾客备注测试。

### 10.3 微信小程序

- 备注输入、计数、提交和详情展示测试。
- 首页公告无数据、正常数据和接口失败测试。
- 公告列表、详情和已下线状态测试。
- 微信客服和电话入口测试。
- 商品归档后列表、搜索、详情、快捷加购和结算测试。
- 原有登录、购物车、下单、订单状态、取货码和账号设置完整回归测试。

## 11. 发布顺序

1. 执行数据库迁移并发布服务端兼容版本。
2. 发布商家后台公告管理和商品归档功能。
3. 配置并验证微信客服能力和门店电话。
4. 发布小程序订单备注、公告和联系商家入口。
5. 使用老板账号完成公告发布和商品删除/恢复验收。
6. 使用顾客账号完成下单、联系商家和归档商品拦截验收。

服务端需要在小程序版本发布前兼容旧客户端：旧客户端未传 `customerNote` 时应按空备注正常创建订单。

## 12. 完成标准

以下条件全部满足后，本次功能才视为完成：

- 四项需求均在对应端可用。
- 权限和审计符合本规格。
- 已删除商品不会出现在顾客端，也不会破坏历史订单。
- 客服不可用时仍可通过电话联系商家。
- 新增测试和既有回归测试全部通过。
- 小程序真机测试与后台浏览器测试均通过。
