# 智慧超市 MVP UI/UX 设计规范

- 项目：鲁能超市李老家分店智慧超市系统
- 适用端：Vue 3 + Element Plus 管理后台、微信原生小程序
- 版本：MVP 1.0
- 日期：2026-07-28
- 依据：
  - `docs/superpowers/specs/2026-07-27-smart-supermarket-mvp-design.md`
  - `docs/superpowers/plans/2026-07-28-smart-supermarket-mvp.md`

## 1. 设计结论

这是乡镇实体超市的日常业务工具，不是营销展示站。设计必须让第一次使用的老板、收银员和顾客不经培训也能找到下一步，并让高频操作在忙碌、弱网、光线复杂的环境中仍然清楚可靠。

设计语言定义为“朴实可信的本地零售”：

- 以暖白背景、深绿色主色和清晰的深色文字建立熟悉、稳重的门店感。
- 后台采用较高信息密度，减少页面跳转，优先呈现订单号、状态、取货人、金额和操作。
- 小程序采用舒适信息密度、大触控区和固定关键操作，适合单手完成浏览、加购和下单。
- 不使用大面积渐变、玻璃拟态、霓虹、纯装饰动画、过度圆角和营销式大标题。
- 不以颜色单独表达状态。状态始终同时包含中文文字，必要时增加图标或说明。
- 默认只设计明亮主题。门店白天使用和商品图片辨识优先，MVP 不增加暗色主题开发与测试成本。

设计旋钮：

| 维度 | 后台 | 小程序 | 说明 |
| --- | ---: | ---: | --- |
| 视觉差异度 | 3/10 | 3/10 | 稳定、可预测、避免模板化装饰 |
| 动效强度 | 2/10 | 2/10 | 仅用于反馈和状态变化 |
| 信息密度 | 7/10 | 4/10 | 后台高效，小程序易读易点 |

## 2. 核心设计原则

### 2.1 下一步必须明确

每个页面只突出一个当前最重要动作。后台订单根据状态显示唯一主动作，例如“接单”“标记备货完成”“完成订单”。小程序根据场景显示“加入购物车”“去结算”或“提交订单”。

### 2.2 业务语言优先

界面只使用门店能理解的中文：

- 使用“线上库存”，不简称为“库存”，避免与线下收银库存混淆。
- 使用“门店微信收款码”，不使用“微信支付”，避免误解为小程序在线支付。
- 使用“待门店确认”“备货中”“待取货”“已完成”“已取消”。
- 使用“收银员账号”，不使用“子用户”“操作员实体”等技术词。

### 2.3 先确认，再改变真实业务状态

接单、拒单、取消、确认付款、完成订单、上下架、库存调整、账号停用和重置密码都改变真实业务数据。操作前说明对象和结果，提交时锁定按钮，成功后以服务器返回为准刷新页面。

### 2.4 弱网可恢复

加载超过 300ms 显示反馈。网络失败必须保留输入和筛选条件，并提供重试。下单网络结果不确定时，禁止直接再次提交，先查询订单结果。

### 2.5 权限透明

无权限的主导航不展示。通过链接进入无权限页面时显示明确的 403 页面，不闪现内容，不只依赖按钮隐藏。权限判断以后端为最终依据。

### 2.6 金额、库存和状态可信

- 金额统一显示为 `¥1,280.00`，使用等宽数字特性。
- 库存使用整数和商品单位，例如 `23 件`。
- 负向或危险操作不使用积极色。
- 订单历史按服务器时间展示，禁止客户端伪造完成状态。

## 3. 统一设计 Token

### 3.1 颜色

所有组件使用语义变量，不在业务组件中直接写十六进制颜色。

| Token | 值 | 用途 |
| --- | --- | --- |
| `color-brand-700` | `#166534` | 主按钮、当前导航、关键链接 |
| `color-brand-800` | `#14532D` | 主按钮悬停、按下 |
| `color-brand-050` | `#F0FDF4` | 选中背景、轻提示背景 |
| `color-accent-600` | `#A16207` | 库存提醒、需要注意的业务信息 |
| `color-accent-050` | `#FFFBEB` | 提醒背景 |
| `color-bg-page` | `#F7F8F4` | 页面背景 |
| `color-bg-surface` | `#FFFFFF` | 表单、表格、弹窗和商品卡片 |
| `color-bg-subtle` | `#F3F4F1` | 次级区域、只读区域 |
| `color-text-primary` | `#1F2937` | 标题、正文和关键数据 |
| `color-text-secondary` | `#4B5563` | 辅助说明 |
| `color-text-muted` | `#6B7280` | 时间、占位和次要信息 |
| `color-border` | `#D8DDD6` | 常规边框和分隔线 |
| `color-border-strong` | `#9CA3AF` | 强调分隔和禁用边界 |
| `color-info-700` | `#1D4ED8` | 信息状态、备货中 |
| `color-info-050` | `#EFF6FF` | 信息状态背景 |
| `color-success-700` | `#166534` | 成功、已完成、已付款 |
| `color-success-050` | `#F0FDF4` | 成功背景 |
| `color-warning-800` | `#92400E` | 警告、待确认、待取货 |
| `color-warning-050` | `#FFFBEB` | 警告背景 |
| `color-danger-700` | `#B91C1C` | 错误、取消、停用和破坏性操作 |
| `color-danger-050` | `#FEF2F2` | 错误背景 |
| `color-scrim` | `rgb(17 24 39 / 48%)` | 弹窗遮罩 |
| `color-focus` | `#2563EB` | 键盘焦点环，和主色区分 |

规则：

- 主色绿色只表达品牌和主要动作，不等同于所有“成功”场景。
- 橙黄色只用于提醒，不作为大面积背景或主要按钮。
- 禁用状态同时使用 `disabled` 语义、降低对比度和禁止交互，不能只改透明度。
- 正文与背景对比度至少 4.5:1，大号文字和非文字控件至少 3:1。

### 3.2 字体与数字

不引入网络字体，优先使用系统中文字体，减少加载失败和字形缺失。

```css
font-family:
  "PingFang SC",
  "Microsoft YaHei",
  "Noto Sans CJK SC",
  system-ui,
  sans-serif;
font-variant-numeric: tabular-nums;
```

| 样式 | 后台 | 小程序 | 字重 | 行高 |
| --- | --- | --- | ---: | ---: |
| 页面标题 | 24px | 22px | 600 | 1.35 |
| 区块标题 | 18px | 18px | 600 | 1.4 |
| 卡片标题 | 16px | 17px | 600 | 1.45 |
| 正文 | 14px | 16px | 400 | 1.6 |
| 辅助文字 | 13px | 14px | 400 | 1.5 |
| 标签文字 | 12px | 13px | 500 | 1.4 |
| 价格主数字 | 20px | 22px | 700 | 1.2 |

小程序正文不低于 14px，主要操作和商品信息优先 16px。后台表格可使用 14px，但操作按钮不得小于 14px。

### 3.3 间距

以 4px 为基础单位：

| Token | 值 | 典型用途 |
| --- | ---: | --- |
| `space-1` | 4px | 图标与短标签 |
| `space-2` | 8px | 紧密控件、按钮组最小间距 |
| `space-3` | 12px | 表单内间距 |
| `space-4` | 16px | 卡片内边距、小程序页面边距 |
| `space-5` | 20px | 表单分组 |
| `space-6` | 24px | 后台区块间距 |
| `space-8` | 32px | 页面主要分区 |
| `space-10` | 40px | 空状态上下留白 |

后台页面左右边距为 24px，最大内容宽度 1440px。小程序手机端左右边距为 16px，大屏设备内容最大宽度 640px 并居中。

### 3.4 圆角

| Token | 值 | 用途 |
| --- | ---: | --- |
| `radius-sm` | 4px | 状态标签、小控件 |
| `radius-md` | 8px | 输入框、按钮、表格容器 |
| `radius-lg` | 12px | 小程序商品卡片、底部操作面板 |
| `radius-full` | 999px | 数量徽标，仅限确需胶囊形的元素 |

禁止将所有卡片、按钮和输入框统一做成超大胶囊形。

### 3.5 阴影和层级

阴影只用于确有浮层关系的组件。

| Token | 值 | 用途 |
| --- | --- | --- |
| `shadow-1` | `0 1px 2px rgb(31 41 55 / 8%)` | 小程序商品卡片 |
| `shadow-2` | `0 8px 24px rgb(31 41 55 / 12%)` | 下拉、抽屉 |
| `shadow-3` | `0 16px 40px rgb(31 41 55 / 18%)` | 模态弹窗 |

| 层级 | z-index |
| --- | ---: |
| 页面内容 | 0 |
| 吸顶筛选、固定操作栏 | 20 |
| 下拉与浮层 | 40 |
| 抽屉 | 60 |
| 模态弹窗 | 80 |
| 全局消息 | 100 |

### 3.6 尺寸和动效

- 后台输入框和按钮默认高 36px，主要操作高 40px。
- 小程序输入框、按钮、数量步进器可触控区域不小于 44px × 44px，相邻触控区至少间隔 8px。
- 图标采用同一图标家族，同一层级统一 2px 描边。禁止使用 emoji 作为结构图标。
- 悬停和焦点过渡为 120-180ms，弹窗进入为 180ms，退出为 120ms。
- 只动画 `opacity` 和 `transform`。加载、提交和状态变化之外不添加动画。
- 尊重 `prefers-reduced-motion`。微信小程序无法读取时，默认保持低动效。

## 4. 双端导航与信息架构

### 4.1 管理后台

桌面结构：

```text
┌──────────────┬────────────────────────────────────────┐
│ 门店名称      │ 顶栏：页面标题 / 当前账号 / 退出         │
│              ├────────────────────────────────────────┤
│ 订单管理      │                                        │
│ 商品管理      │               页面内容                  │
│ 分类管理      │                                        │
│ 线上库存      │                                        │
│ 员工管理      │                                        │
│ 操作日志      │                                        │
└──────────────┴────────────────────────────────────────┘
```

- 侧栏展开宽 208px，折叠宽 64px，顶栏高 56px。
- 老板登录后默认进入“订单管理”，因为订单处理是每日首要任务。
- 收银员只显示“订单管理”，默认进入订单列表。
- 老板导航顺序：订单管理、商品管理、分类管理、线上库存、员工管理、操作日志。
- 当前导航使用左侧 3px 绿色标记、浅绿背景和加粗文字。不能只改变文字颜色。
- 退出登录位于账号菜单底部，并与业务导航分离。
- 页面深度达到三级时使用面包屑，例如“订单管理 / 订单详情 / 202607280001”。

后台权限矩阵：

| 页面或动作 | 老板 OWNER | 收银员 CASHIER |
| --- | --- | --- |
| 订单列表与详情 | 可用 | 可用 |
| 接单、拒单、备货完成、付款、完成、取消 | 可用 | 可用 |
| 商品、分类、图片、上下架 | 可用 | 不展示，路由拒绝 |
| 线上库存调整 | 可用 | 不展示，路由拒绝 |
| 员工管理 | 可用 | 不展示，路由拒绝 |
| 操作日志 | 可用 | 不展示，路由拒绝 |

### 4.2 微信小程序

底部导航固定为 3 项：

1. 首页
2. 购物车
3. 订单

规则：

- 图标与文字同时展示，当前项使用深绿色。
- 购物车角标只显示选中和未选中商品总件数，超过 99 显示 `99+`。
- 搜索属于首页内容，不增加独立底部导航。
- 商品详情、结算和订单详情是二级页面，使用微信原生返回行为。
- 返回列表时恢复搜索词、分类、滚动位置和分页结果。
- 结算页和订单详情页的底部操作栏必须避开安全区，并为滚动内容预留等高底部空间。

小程序结构：

```text
首页
├── 搜索结果
├── 分类筛选
└── 商品详情
    └── 加入购物车

购物车
└── 结算
    ├── 微信登录
    ├── 取货信息
    └── 提交成功 -> 订单详情

订单
└── 订单详情
    └── 待门店确认时取消订单
```

## 5. 管理后台页面规范

### 5.1 登录页 `/login`

布局：

- 暖白全屏背景，居中单列登录面板，宽 400px，手机端左右保留 16px。
- 顶部显示门店名称“鲁能超市李老家分店”和“智慧超市管理后台”。
- 字段顺序：用户名、密码。标签常驻，密码支持显示或隐藏。
- 主按钮“登录”占满表单宽度。
- 底部提示“仅限门店工作人员使用”。

状态：

- 未填写时提交，在对应字段下显示“请输入用户名”“请输入密码”，焦点移到第一个错误字段。
- 登录中按钮显示加载并禁用表单，防止重复提交。
- 账号或密码错误显示在表单顶部警告区，不清空用户名，只清空密码。
- 账号停用明确提示“账号已停用，请联系老板处理”。
- 网络错误保留输入并提供“重新登录”。

### 5.2 订单列表 `/orders`

页面目标：在 10 秒内判断有哪些新订单、哪些订单待处理，并进入正确操作。

布局顺序：

1. 页面标题“订单管理”和刷新按钮。
2. 状态分段筛选：全部、待门店确认、备货中、待取货、已完成、已取消。
3. 筛选栏：付款状态、关键词、查询、重置。关键词占位提示“订单号 / 取货人 / 手机号”。
4. 结果摘要，例如“共 28 笔订单”。
5. 订单表格。
6. 分页。

表格列：

| 列 | 规则 |
| --- | --- |
| 订单号 | 等宽数字，可复制，点击进入详情 |
| 下单时间 | `2026-07-28 14:35` |
| 取货人 | 姓名主行，手机号次行；默认完整展示仅限有权限员工 |
| 商品 | 显示“3 种 / 5 件”，悬停可看名称摘要 |
| 金额 | 右对齐，`¥58.90` |
| 订单状态 | 使用状态标签 |
| 付款状态 | 使用付款标签 |
| 操作 | “查看详情”为稳定入口，当前合法主动作最多一个 |

交互：

- 默认按下单时间倒序。
- “待门店确认”标签显示数量，刷新后更新。
- 筛选条件写入 URL 查询参数，返回列表时保留。
- 订单状态切换后刷新当前行和顶部计数，不做未经服务器确认的乐观更新。
- 表格加载使用 8 行骨架，不显示空白表格加全屏转圈。
- 无结果时区分“还没有订单”和“当前筛选没有结果”。

### 5.3 订单详情 `/orders/:orderNo`

桌面双栏布局：

```text
┌──────────────────────────────────┬────────────────────┐
│ 订单号、状态、付款状态             │ 当前可执行操作       │
│ 商品明细                           │ 取货信息             │
│ 金额汇总                           │ 订单状态记录         │
│ 取消信息，存在时显示                │                     │
└──────────────────────────────────┴────────────────────┘
```

- 主栏约占 2/3，侧栏约占 1/3。
- 订单号提供复制按钮，复制成功使用非阻断消息。
- 商品明细展示图片、名称快照、单位快照、单价、数量和小计。
- 金额区只展示商品总额与合计，MVP 没有配送费、优惠或在线支付。
- 取货信息展示姓名和手机号，手机号提供复制，不提供外呼集成。
- 时间线从新到旧或从旧到新必须全站一致。本规范采用从旧到新，最新节点位于底部并自动可见。

合法动作：

| 当前订单状态 | 付款状态 | 主动作 | 次动作 |
| --- | --- | --- | --- |
| 待门店确认 | 未付款 | 接单 | 拒单 |
| 备货中 | 未付款 | 标记备货完成 | 取消订单 |
| 待取货 | 未付款 | 确认付款 | 取消订单 |
| 待取货 | 已付款 | 完成订单 | 取消订单 |
| 已完成 | 已付款 | 无 | 无 |
| 已取消 | 任意 | 无 | 无 |

操作规则：

- 非法动作不展示。状态在其他窗口已变化时，服务器冲突信息展示在页面顶部，并立即刷新详情。
- “接单”“标记备货完成”“确认付款”“完成订单”使用确认弹窗。
- “拒单”和“取消订单”使用危险确认弹窗，原因必填，2-200 字。
- 确认付款弹窗必须选择“现金”或“门店微信收款码”，默认不预选，避免忙中误点。
- 完成订单前同时展示付款方式和付款时间，未付款时不展示完成入口。

### 5.4 商品管理 `/products`

布局：

1. 标题与主按钮“新增商品”。
2. 筛选：关键词、分类、上下架状态、查询、重置。
3. 商品表格。
4. 分页。

表格列：

- 商品图片，48px × 48px，4:3 内容使用 `object-fit: cover`。
- 商品名称。
- 分类。
- 售价，右对齐。
- 单位。
- 上下架状态。
- 更新时间。
- 操作：编辑、上架或下架。

新增和编辑使用右侧抽屉，桌面宽 560px，小屏占满宽度。字段：

1. 商品名称，必填，最长值以后端约束为准。
2. 分类，必填。
3. 售价，按元输入，最多两位小数，提交转为分。
4. 单位，必填，例如“袋”“瓶”“箱”。
5. 商品图片，JPEG、PNG、WebP，最大 5 MiB。
6. 商品详情，可选。
7. 上下架开关。

规则：

- 图片上传显示本地预览、进度、失败原因和重新上传。
- 上传成功后使用服务端返回 URL，不能使用原文件名作为业务信息。
- 关闭有未保存内容的抽屉时二次确认。
- 下架确认说明“小程序将不再展示该商品，历史订单不受影响”。
- 售价输入旁固定显示“元”，错误示例明确为“请输入最多两位小数的非负金额”。

### 5.5 分类管理 `/categories`

单页表格，不使用卡片墙。

列：分类名称、排序、启用状态、更新时间、操作。

- 新增分类使用小弹窗，字段为名称、排序、启用状态。
- 编辑可复用同一弹窗。
- 排序使用非负整数，数值越小越靠前，界面提供常驻说明。
- 停用前说明“该分类将不在小程序显示，分类下商品数据不会删除”。
- MVP 不增加拖拽排序，避免无键盘替代和误操作。

### 5.6 线上库存 `/inventory`

页面顶部放置固定说明：

> 此处仅管理小程序可售数量，不会自动同步线下收银库存。

筛选：商品名称、分类、库存状态。

表格列：商品、分类、线上可售、单位、上下架状态、最后调整时间、操作。

库存状态：

- `0`：显示“无库存”，危险色文字。
- `1-5`：显示“库存较低”，警告色文字。
- `>5`：显示具体数量，不额外添加绿色标签。

调整库存弹窗：

- 显示商品名和当前线上库存。
- 字段“调整数量”，正数增加，负数减少，禁止 0。
- 实时显示预计结果，例如“23 件 -> 18 件”。
- 字段“调整原因”，必填，2-100 字。
- 预计结果小于 0 时禁用提交并显示“调整后库存不能小于 0”。
- 提交成功后刷新该行，以服务器库存为准。

### 5.7 员工管理 `/staff`

仅老板可见。

表格列：用户名、角色、状态、最后登录、创建时间、操作。

- 角色在 MVP 固定为“收银员”，不提供自定义角色。
- 新增收银员弹窗字段：用户名、初始密码、确认密码。
- 密码规则常驻显示，不只在出错后显示。
- 新建成功仅当次展示初始密码，提示老板安全交付，不提供再次查看。
- 停用账号使用危险确认，说明“该账号现有登录将失效”。
- 启用账号使用普通确认。
- 重置密码需二次确认，新密码仅当次展示并支持复制。
- 永不展示密码哈希、JWT、会话 ID 或其他敏感值。

### 5.8 操作日志 `/audit-logs`

仅老板可见，只读。

筛选：操作人、操作类型、业务对象、时间范围、查询、重置。

表格列：时间、操作人、操作、对象、结果摘要、请求编号。

- 结果摘要最多两行，超出省略，悬停或点击查看完整内容。
- 请求编号使用等宽数字并可复制，方便排查问题。
- 不提供删除、编辑或导出，MVP 只支持查询。
- 空状态文案“暂无符合条件的操作记录”。

### 5.9 403、404 和会话失效

- 403 标题“无权访问此页面”，说明当前账号角色，并提供“返回订单管理”。
- 404 标题“页面不存在”，提供“返回订单管理”。
- 会话失效先保存当前页面地址，提示“登录已过期，请重新登录”，清理本地令牌并跳转登录。重新登录后回到原合法页面。
- 收银员访问老板页面时不可短暂渲染敏感内容。

## 6. 微信小程序页面规范

### 6.1 首页

布局：

```text
┌──────────────────────────┐
│ 鲁能超市李老家分店         │
│ [ 搜索商品名称          ] │
│ 分类横向栏                 │
│ 商品列表                   │
│ 商品列表                   │
├──────────────────────────┤
│ 首页       购物车      订单 │
└──────────────────────────┘
```

- 顶部显示门店名称，不显示虚构促销横幅。
- 搜索框常驻，提交搜索或清空搜索时刷新列表。
- 分类首项为“全部”，后接启用分类。分类可横向滚动，但选中项必须完整可见。
- 商品采用两列卡片。320px 以下或系统大字体导致拥挤时切为单列。
- 商品卡片包含 4:3 图片、最多两行名称、价格、单位、库存提示和“加入”按钮。
- 商品无库存时按钮变为“已售罄”并禁用，不隐藏商品详情入口。
- 点击卡片主体进入详情，点击“加入”只加购，不触发跳转。
- 分页使用触底加载，底部显示“没有更多商品了”，避免重复请求。

### 6.2 搜索和分类结果

- 搜索词显示在输入框中，结果摘要为“找到 8 件商品”。
- 搜索防抖 300ms，但按键盘搜索键立即执行。
- 无结果文案“没有找到相关商品”，提供“清空搜索”。
- 加载失败显示“商品加载失败，请检查网络后重试”和“重新加载”。
- 切换分类时回到列表顶部，但返回商品详情时恢复之前位置。

### 6.3 商品详情

内容顺序：

1. 商品主图，4:3，预留尺寸避免跳动。
2. 商品名。
3. 价格与单位。
4. 线上库存状态。
5. 商品详情。
6. 底部固定操作栏：购物车入口、数量反馈、加入购物车。

规则：

- 价格采用 `¥5.90 / 盒`。
- 不展示虚构销量、评分、原价、优惠券或配送承诺。
- 商品下架或不存在时显示“商品暂不可购买”，提供“返回首页”。
- 点击加入后按钮在 150ms 内反馈，并以简短提示“已加入购物车”确认。
- 底部操作栏避开安全区。

### 6.4 购物车

列表项包含：

- 选择框。
- 商品图。
- 商品名、当前显示价格和单位。
- 数量步进器，减号、数量、加号。
- 删除入口。

底部固定结算栏：全选、合计、去结算。

规则：

- 数量最小为 1。点减号到 1 时不自动删除，删除必须由明确入口触发。
- 删除使用确认动作，文案包含商品名。
- 合计只计算选中商品。
- 未选择商品时“去结算”禁用，并提示“请选择要结算的商品”。
- 商品价格是展示参考。结算提交由后端重新确认价格和库存。
- 本地购物车商品下架、价格变化或库存不足时，在对应行显示问题和解决动作，不让用户猜测。
- 空购物车显示“购物车还是空的”，主动作“去逛逛”。

### 6.5 结算页

页面是单步确认，不拆成多步向导。

内容顺序：

1. 到店自取提示。
2. 取货信息。
3. 商品清单。
4. 合计。
5. 付款说明。
6. 底部固定“提交订单”。

取货信息：

- 字段“取货人姓名”，必填，最长 40 字。
- 字段“手机号”，必填，使用数字电话键盘，校验 `^1\d{10}$`。
- 已有资料时自动填入，但允许修改并保存。
- 微信登录在点击结算或提交前按需触发，不在浏览商品时强制登录。

付款说明固定写明：

> 到店后使用现金或门店微信收款码付款。小程序内不收款。

提交规则：

- 按钮显示合计，例如“提交订单 ¥58.90”。
- 提交中禁用返回以外的重复操作，按钮显示“正在提交”。
- 成功后只移除本次已购买商品，并跳转订单详情。
- 后端返回商品下架、价格变化或库存不足时，在商品清单对应行展示，提供“返回购物车处理”。
- 网络结果不确定时显示“正在确认订单结果”，自动查询订单，不生成新请求标识。
- 确认无结果后才允许用户重试原请求。界面不得引导反复点击。

### 6.6 订单列表

顶部筛选：全部、待处理、已结束。

- “待处理”包含待门店确认、备货中、待取货。
- “已结束”包含已完成、已取消。

订单卡片内容：

- 订单状态和下单时间。
- 前 2 个商品名称，更多显示“等 N 件商品”。
- 总件数和合计。
- 付款状态。
- 订单号简写，详情页展示完整订单号。
- 操作“查看详情”。待门店确认时可显示次操作“取消订单”。

卡片按下单时间倒序。空状态区分“还没有订单”和“当前分类没有订单”。

### 6.7 订单详情

信息顺序：

1. 当前状态大标题和一句下一步说明。
2. 商品明细。
3. 合计和付款状态。
4. 取货人信息。
5. 订单号和下单时间。
6. 状态进度。
7. 取消信息，存在时展示。
8. 底部操作，只有待门店确认显示“取消订单”。

状态说明：

| 状态 | 顾客说明 |
| --- | --- |
| 待门店确认 | 门店正在确认商品，请稍候 |
| 备货中 | 门店已接单，正在为您备货 |
| 待取货 | 商品已备好，请到店付款取货 |
| 已完成 | 本次订单已完成 |
| 已取消 | 订单已取消 |

规则：

- “待取货”优先展示门店名称和付款说明，不虚构地址、营业时间或电话。
- 接单后不显示取消按钮，改为提示“如需取消，请联系门店处理”。
- 顾客取消待确认订单时使用底部确认面板，明确“取消后库存会释放，本操作不能撤销”。
- 状态记录采用纵向时间线，包含中文状态和时间。

## 7. 组件规范

### 7.1 按钮

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| 主要按钮 | 页面唯一主动作 | 接单、提交订单、新增商品 |
| 次要按钮 | 可逆或次级动作 | 重置、返回、查看详情 |
| 文字按钮 | 表格行内低风险动作 | 编辑、复制 |
| 危险按钮 | 破坏性操作 | 取消订单、停用账号、下架 |

规则：

- 同一区域最多一个主要按钮。
- 提交期间显示加载并禁用，不改变按钮宽度。
- 图标按钮必须有可访问名称和提示。
- 危险操作不得用绿色主要按钮。
- 小程序底部主按钮高度 48px，左右边距 16px。

### 7.2 表格

- 表头背景使用 `color-bg-subtle`，文字 13px、字重 600。
- 行高默认 56px，商品图行可为 64px。
- 金额和数量右对齐，名称左对齐，状态居中或左对齐但全站一致。
- 表格不使用斑马纹，使用单一底部分隔线和悬停背景。
- 行操作不超过 3 个。更多操作进入“更多”菜单。
- 分页每页默认 20 条，可选 20、50、100。
- 超过 50 行仍通过分页处理，MVP 不引入虚拟滚动。

### 7.3 表单

- 标签在输入框上方，不使用占位符代替标签。
- 必填星号紧随标签，并提供“* 为必填项”说明。
- 复杂字段说明常驻在输入框下方。
- 失焦后校验，提交时完整校验。
- 错误显示在对应字段下，多个错误时将焦点移到第一个错误字段。
- 只读与禁用视觉不同。只读内容仍可选择复制，禁用控件不可交互。
- 金额输入只接受非负数字和最多两位小数，库存调整只接受整数。

### 7.4 弹窗、抽屉和底部面板

- 短确认使用弹窗，长表单使用抽屉，小程序确认使用底部面板。
- 标题必须包含业务对象，例如“取消订单 202607280001”。
- 正文说明操作后果，不使用“确定执行吗”这类无上下文文案。
- 按钮顺序：后台左侧取消、右侧确认；小程序上方主要动作、下方取消或并排时主要动作在右。
- 危险确认按钮使用危险色，不能默认聚焦。
- 提交中禁止关闭。提交失败后保留输入并恢复操作。
- 有未保存内容时关闭必须确认。

### 7.5 状态标签

- 高 24px，圆角 4px，左右内边距 8px。
- 由“浅色背景 + 深色文字”构成，不使用纯色实心胶囊堆满表格。
- 状态标签文字不得缩写。
- 同一业务对象的状态颜色在双端一致。

### 7.6 商品卡片和图片

- 商品图统一 4:3 比例，列表预留固定空间。
- 缺图时使用中性占位，显示“暂无图片”，不使用随机图库图片。
- 图片加载失败显示占位，但商品名称和操作仍可用。
- 小程序卡片只显示购买决策所需信息，避免加入分类标签、销量、折扣等 MVP 外信息。

### 7.7 数量步进器

- 减号和加号可触控区各不小于 44px。
- 当前数量居中，宽度足够容纳 3 位数。
- 达到最小或业务最大值时对应按钮禁用。
- 快速连点需要节流，并保证最终是正整数。

### 7.8 消息和通知

- 表单错误使用字段内联提示。
- 页面加载错误使用页面内错误区。
- 服务器冲突使用页面顶部常驻警告，直到用户刷新或处理。
- 短暂成功使用消息提示，3 秒后消失。
- 重要操作成功后同时更新页面内容，不能只依赖 toast。

## 8. 状态映射

### 8.1 订单状态

| 后端值 | 中文 | 色彩 | 后台动作提示 | 小程序下一步 |
| --- | --- | --- | --- | --- |
| `PENDING_CONFIRMATION` | 待门店确认 | 警告 | 尽快接单或拒单 | 等待门店确认，可取消 |
| `PREPARING` | 备货中 | 信息 | 备货完成后更新状态 | 等待门店备货 |
| `READY_FOR_PICKUP` | 待取货 | 警告 | 到店后确认付款并完成 | 到店付款取货 |
| `COMPLETED` | 已完成 | 成功 | 无后续动作 | 流程结束 |
| `CANCELLED` | 已取消 | 危险或中性 | 查看取消方和原因 | 查看取消原因 |

### 8.2 付款状态和方式

| 后端值 | 中文 | 样式或展示 |
| --- | --- | --- |
| `UNPAID` | 未付款 | 警告背景，文字标签 |
| `PAID` | 已付款 | 成功背景，文字标签 |
| `CASH` | 现金 | 付款方式正文 |
| `WECHAT_QR` | 门店微信收款码 | 付款方式正文 |

禁止把 `WECHAT_QR` 显示成“小程序微信支付”或“在线支付”。

### 8.3 其他业务状态

| 对象 | 状态 | 中文和表现 |
| --- | --- | --- |
| 商品 | `onShelf=true` | 已上架，成功标签 |
| 商品 | `onShelf=false` | 已下架，中性标签 |
| 分类 | `enabled=true` | 已启用，成功标签 |
| 分类 | `enabled=false` | 已停用，中性标签 |
| 员工 | `enabled=true` | 正常，成功标签 |
| 员工 | `enabled=false` | 已停用，危险或中性标签 |
| 库存 | `0` | 无库存，危险文字 |
| 库存 | `1-5` | 库存较低，警告文字 |
| 库存 | `>5` | 直接显示数量 |

阈值 `5` 是前端展示建议，不代表自动补货业务规则。若后端未来提供库存阈值，应以后端为准。

### 8.4 API 错误到界面行为

| 错误码 | 用户文案原则 | 界面行为 |
| --- | --- | --- |
| `VALIDATION_ERROR` | 指出哪个字段以及修正方式 | 字段内联错误，聚焦首个错误 |
| `NOT_FOUND` | 对象不存在或已被删除 | 页面级空状态，提供返回 |
| `ORDER_STATE_CONFLICT` | 订单状态已变化 | 不覆盖本地，刷新详情 |
| `INSUFFICIENT_STOCK` | 指出库存不足商品 | 对应商品行标记，返回购物车处理 |
| `FORBIDDEN` | 当前账号无权限 | 403 页面，不展示敏感内容 |
| `RATE_LIMITED` | 操作过于频繁，请稍后再试 | 禁用短时间重复操作，显示恢复建议 |
| `INTERNAL_ERROR` | 操作失败并展示请求编号 | 保留输入，提供重试或联系门店 |
| 网络超时 | 网络连接不稳定 | 保留状态，提供重试；下单先查结果 |

所有错误响应若带 `requestId`，后台错误详情中显示“问题编号”，小程序在可联系门店的失败场景显示“问题编号”，方便排查。

## 9. 空、加载、错误和权限状态

### 9.1 加载

- 首屏内容预计超过 300ms 时显示与最终结构一致的骨架。
- 按钮操作使用按钮内加载，不遮挡整个页面。
- 翻页时保留表头和页面结构，表体显示骨架。
- 小程序触底加载只在列表底部显示，不用全屏加载。
- 图片预留比例，避免加载后布局跳动。

### 9.2 空状态

| 场景 | 文案 | 动作 |
| --- | --- | --- |
| 后台没有商品 | 还没有商品 | 新增商品 |
| 筛选无商品 | 没有符合条件的商品 | 清空筛选 |
| 后台没有订单 | 还没有订单 | 刷新 |
| 小程序无搜索结果 | 没有找到相关商品 | 清空搜索 |
| 购物车为空 | 购物车还是空的 | 去逛逛 |
| 顾客没有订单 | 还没有订单 | 去首页选购 |
| 操作日志为空 | 暂无符合条件的操作记录 | 清空筛选 |

空状态不使用夸张插画。可使用同一图标家族的简单线性图标、标题、说明和一个动作。

### 9.3 错误状态

- 错误文案包含发生了什么和怎么恢复。
- 不能只显示“出错了”“请求失败”。
- 页面局部错误不替换整个应用壳。
- 重试按钮必须重试原操作，不能默默跳首页。
- 连续失败保留请求编号。

### 9.4 权限和隐私

- 收银员看不到老板导航和相关页面数据。
- 后台手机号仅对履约所需员工展示，不在日志摘要中完整复制。
- 小程序只展示当前顾客自己的订单。
- 密码、密码哈希、令牌、微信会话密钥、环境配置永不进入页面。
- 屏幕阅读器不朗读被视觉隐藏但无权限的内容，因为内容根本不渲染。

## 10. 响应式与移动端规则

### 10.1 管理后台

| 宽度 | 规则 |
| --- | --- |
| `>=1440px` | 内容最大宽 1440px，侧栏展开，筛选单行 |
| `1024-1439px` | 侧栏可折叠，筛选允许两行，表格保持 |
| `768-1023px` | 侧栏默认折叠为图标加提示，详情双栏改为单栏 |
| `<768px` | 顶栏菜单抽屉，表格改为关键字段卡片，操作使用底部面板 |

后台主要工作环境建议不低于 1024px，但不能在小屏上出现横向溢出或无法完成关键订单操作。移动卡片只保留订单号、时间、取货人、金额、状态和主动作，其余进入详情。

### 10.2 微信小程序

- 基准测试宽度：320px、375px、430px。
- 兼容横屏和大字体，禁止锁定缩放或固定像素高度截断内容。
- 320px 下商品列表允许单列，底部按钮文案不得换成两行。
- 平板和桌面微信环境中内容最大宽 640px 并居中，不无限拉伸。
- 固定底栏使用安全区内边距，列表底部内边距至少为底栏高度加 16px。
- 不使用横向滑动作为关键动作。分类横向滚动之外，所有关键动作有可见按钮。
- 键盘弹出时确保当前字段和错误信息可见，提交栏不得遮挡输入。

## 11. 可访问性

### 11.1 后台 Web

- 所有功能支持键盘完成，Tab 顺序与视觉顺序一致。
- 页面提供“跳到主要内容”链接。
- 路由切换后焦点移到页面标题。
- 焦点环使用 2px `color-focus`，与控件间隔 2px，不移除浏览器焦点。
- 图标按钮提供 `aria-label`，状态变化使用 `aria-live="polite"`。
- 弹窗打开后焦点进入标题或首个字段，关闭后回到触发按钮。
- 表格排序列使用 `aria-sort`。没有排序能力时不显示排序图标。
- 错误汇总和字段错误可被屏幕阅读器感知。
- 手机号、订单号、金额等数字使用可理解的文字标签，不能依靠列位置。

### 11.2 微信小程序

- 所有图片提供有意义的替代描述。装饰图不重复朗读。
- 图标按钮补充可访问名称，例如“减少纯牛奶数量”。
- 触控区至少 44px，间距至少 8px。
- 选择、禁用、展开等状态需要可被读屏识别。
- 系统字体放大后允许文字换行，不把正文截断成不可理解的省略号。
- 状态不仅靠颜色，也包含完整中文。
- 返回、关闭、取消路径清楚，不使用手势作为唯一方式。

## 15. 视觉验收清单

### 15.1 品牌与一致性

- [ ] 双端看起来属于同一门店，使用同一绿色、暖白、中性色和状态语义。
- [ ] 后台比小程序紧凑，但没有缩小到难读难点。
- [ ] 页面没有 AI 紫色渐变、玻璃拟态、霓虹外发光、纯装饰动画或营销大字。
- [ ] 圆角遵循 4px、8px、12px 规则，没有无理由混用胶囊和直角。
- [ ] 阴影只用于真实浮层，普通表格和分区主要用边框和留白。
- [ ] 图标来自同一图标家族，没有 emoji 结构图标。

### 15.2 清晰度与效率

- [ ] 每页只有一个视觉主动作。
- [ ] 老板和收银员进入订单列表后能立即看到待处理订单。
- [ ] 订单详情无需猜测当前可执行动作。
- [ ] “线上库存”和“线下库存不同步”在相关页面明确可见。
- [ ] “到店付款”在结算和待取货状态明确可见。
- [ ] 表格金额、数量和时间对齐稳定。
- [ ] 文案使用门店日常语言，没有技术枚举或模糊提示。

### 15.3 状态完整性

- [ ] 每个列表均验收加载、正常、无数据、筛选无结果、网络错误。

- [ ] 后台可只用键盘完成登录、筛选、订单处理和关闭弹窗。

- [ ] 加载图片和异步内容不会造成明显布局跳动。

## 16. 非目标和后续扩展边界

本规范不包含：

- 数据分析仪表盘。
- 配送地址、配送费和配送进度。
- 小程序在线支付。
- 会员、积分、余额和优惠券。
- 称重商品、预定、定金和尾款。
- 扫码购物、扫码收银和电子小票。
- 营销活动、推荐、销量排行和自动补货。
- 暗色主题。

后续增加功能时，继续复用本规范的语义 token、状态反馈、权限透明和弱网恢复原则。新增导航项必须先验证用户任务频率，不能因功能增长把小程序底部导航扩展到 5 项以上，也不能把后台高频订单入口挤到二级菜单。
