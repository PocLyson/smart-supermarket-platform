# 顾客与门店消息本地验收

## 1. 验收范围

本轮提供站内客服消息 MVP：顾客登录后可以从“我的”或订单详情联系门店；老板和收银员可以在商家小程序消息中心查看并回复。消息采用 10 秒可见态轮询，不是微信订阅消息，也不会在小程序退出后推送系统通知。

## 2. 启动环境

在仓库根目录启动 MySQL、Redis 和服务端：

```powershell
docker compose up -d
cd server
.\mvnw.cmd spring-boot:run
```

确认 `http://localhost:8080/actuator/health` 返回 `UP`。随后分别在微信开发者工具导入 `mini/` 和 `merchant-mini/`，执行“工具 → 构建 npm”。本地联调可临时关闭合法域名校验；真机和体验版必须使用已配置的 HTTPS 合法域名。

## 3. 顾客端检查

1. 登录顾客小程序，进入“我的”。未登录时不应显示联系门店与拨打电话操作。
2. 点击“联系在线客服”，应进入“联系门店”会话页。
3. 输入一条消息并发送，只出现一条顾客消息；断网后重试同一内容也不得生成重复消息。
4. 从某个订单详情点击“联系在线客服”，页面顶部应显示关联订单，发送后消息应带订单标签。
5. 页面隐藏或小程序进入后台时停止轮询；重新显示后继续加载门店回复。

## 4. 商家端检查

1. 使用老板或收银员账号登录商家小程序，点击底部“消息”。
2. 新顾客消息应显示顾客称呼、脱敏手机号、摘要、关联订单和未读徽标，不显示 openid 或完整敏感标识。
3. 进入会话后未读数应清除；回复消息后顾客端在重新显示或最多约 10 秒后看到门店回复。
4. 工作台“待回复”数量应与存在未读顾客消息的会话数一致，点击该指标进入消息中心。
5. 老板和收银员都应能读取和回复；未登录或错误客户端令牌必须被服务端拒绝。

## 5. 异常与隐私检查

- 空消息和超过 500 个字符的消息不得发送。
- 顾客不能访问其他顾客的会话，也不能关联其他顾客的订单。
- 网络错误后页面保留输入内容并允许重试；重试复用同一消息标识，避免重复发送。
- 截图与验收记录需遮盖手机号、顾客姓名、订单号、JWT、openid 和取货码。
- 本功能暂不支持图片、文件、撤回、离线系统通知、聊天记录搜索和人工分配坐席。

## 6. 本轮自动验证基线

2026-08-13 本地全量回归结果：服务端 36 个测试套件、121 项通过；顾客小程序 37 个测试文件、146 项通过并完成类型检查；商家小程序 10 个测试文件、131 项通过并完成类型检查。自动验证不能替代微信开发者工具和双端人工闭环验收。
